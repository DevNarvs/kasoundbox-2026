# Week-1 Spike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the risky technical parts of the stack on the real free services in Singapore, then record a go/no-go decision before Foundation starts.

**Architecture:** A small, throwaway Next.js app in `spike/`, deployed to the **test** Vercel project (`sin1`) and backed by the **test** Supabase project (Singapore), separate from production (D-28). Each week-1 item is settled by one probe: a route, page, script, or workflow that prints `PASS`/`FAIL` against its criteria from the test plan. The results are recorded in a kept results note. The probe code is deleted at the end (D-32).

**Tech Stack:**
- Next.js 16.4.2 and React 19.3.1, TypeScript strict
- `pg` 8.23.1 with `pg-pool` 3.14.0, and `@vercel/functions` 3.10.2
- Better Auth 1.7.12 and `@node-rs/argon2` 2.2.2
- `@supabase/supabase-js` 2.118.0
- `@yudiel/react-qr-scanner` 2.6.0 and `uqr`
- Resend REST API, `@sentry/nextjs`
- Supabase CLI, `pg_cron`, `pg_net`, Vault
- GitHub Actions with `age`
- `tsx` for scripts

**Spec:** The week-1 checklist in [`docs/06-delivery/test-plan.md`](../../06-delivery/test-plan.md) §4 (cases TC-W1-01 to TC-W1-09), [`docs/05-technical/architecture.md`](../../05-technical/architecture.md) §14.1, and the week-1 phase in [`docs/06-delivery/roadmap.md`](../../06-delivery/roadmap.md) §1.4. Background: the frozen [design spec](../specs/2026-10-21-kasoundbox-design.md) §17.

## Who does what

Each task is tagged.
- **[Claude]** writes the code.
- **[Developer]** (the Super Admin) creates accounts, sets secrets, runs deploys, and does the manual checks.
- **[Admin]** (the business owner) joins the QR test.

This cloud session cannot reach vercel.com, and it cannot push to GitHub while the 403 error persists (O-07). So every **deploy** and **run against the real services** step happens on the developer's machine, with this repository checked out.

## Global Constraints

- Only the **test** project is used, never production (D-28). Production is created fresh just before launch.
- All probe code lives in `spike/`, plus `.github/workflows/spike-backup.yml`, and is deleted in Task 10 (D-32). The kept output is `docs/06-delivery/week1-results.md` and the updated docs.
- **Regions.** `vercel.json` has `"regions": ["sin1"]`. The Supabase region is "Southeast Asia (Singapore)".
- **Pool.** `new Pool({ max: 1, min: 0, idleTimeoutMillis: 5_000, connectionTimeoutMillis: 5_000, query_timeout: 10_000, ssl: { ca: SUPABASE_DB_CA, rejectUnauthorized: true } })`, then `attachDatabasePool(pool)`.
  - `DATABASE_URL` uses the **transaction pooler, port 6543**, as `app_rw.<project-ref>`, with no `sslmode` in the URL.
  - Never use `postgres.js`, named prepared statements, session `SET`, or session advisory locks.
- **`app_rw` role.** SCRAM password, no `VALID UNTIL`. `statement_timeout '5s'`, `lock_timeout '2s'`, `idle_in_transaction_session_timeout '10s'`.
- **`app_backup` role.** Login, `default_transaction_read_only = on`, `SELECT` only. Used through the **session pooler, port 5432**.
- **Functions.** Every probe function is `SECURITY DEFINER`, owned by `app_owner` (NOLOGIN), with `SET search_path = ''`.
- **argon2id.** `m = 19456` KiB, `t = 2`, `p = 1`. Fallback: `node:crypto` scrypt with `N = 2^17`, `r = 8`, `p = 1`, `maxmem = 256 MiB`.
- **Admin session cookie.** `HttpOnly`, `Secure`, `SameSite=Strict`, `__Secure-` prefix.
- **Environment variable names** are exactly those in architecture §8.1 and §8.2. Spike-only additions are `SPIKE_DIRECT_DATABASE_URL` and `SPIKE_SESSION_POOLER_URL`.
- **Secrets.** No secret value is ever committed. `spike/.env.example` lists the names with empty values.
- **Time.** Times are shown in Manila time with `Intl.DateTimeFormat(..., { timeZone: 'Asia/Manila' })`. `TZ` is never set.
- **Probe output.** Every probe prints one line per check, `PASS <check-id> <detail>` or `FAIL <check-id> <detail>`, and exits non-zero if any check fails. Check IDs match the rows of the results note.

## Review Focus

1. **Cold start after idle.** On Hobby, the first request after about 15 idle minutes can be much slower than a warm one. Pin this with the latency probe's `cold` sample (Task 2).
2. **Pooler clients leaking under bursts.** After the race and load runs, the pooler client count must return to its idle level. Pin this with the before/after client-count check (Tasks 3 and 9).
3. **Manila date versus UTC.** Near midnight in Manila, the server's "today" must be the Manila date, not the UTC date. Pin this with the `manila_today` check (Task 2).
4. **Camera permission denied.** If the browser blocks the camera (iOS Safari prompt refused), the admin must still be able to look up the QR. Pin this with the denied-permission case (Task 7).
5. **Supabase pausing the free project.** A week with few visitors must not pause it. Pin this with the keep-alive watch over 7 days (Task 5).

```sql
create function app.spike_book(p_date date) returns jsonb
language plpgsql security definer set search_path = '' as $$
declare v_resource int;
begin
  perform 1 from app.capacity_lock where id = 1 for update;
  select r.id into v_resource from app.resources r
   where r.kind = 'delivery_set' and r.active
     and not exists (select 1 from app.resource_claims c
                     where c.resource_id = r.id and c.claim_date = p_date and c.live)
   order by r.id limit 1;
  if v_resource is null then return jsonb_build_object('code', 'sold_out'); end if;
  insert into app.resource_claims(resource_id, claim_date, live) values (v_resource, p_date, true);
  return jsonb_build_object('code', 'ok', 'resource_id', v_resource);
end $$;
alter function app.spike_book(date) owner to app_owner;
grant execute on function app.spike_book(date) to app_rw;
```
